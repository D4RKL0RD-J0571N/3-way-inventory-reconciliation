## 1. Executive Summary & Architectural Positioning

Despite the **ReconcileAI** product branding across `requirements.txt:1`, `app.py:314,1748`, `src/i18n.py:22–27`, and `tools/build_exe.py`, the current repository contains **zero** AI, OCR, PDF, email, vector-store, graph, LLM, legacy `.xls`, or MCP capabilities (`requirements.txt` declares only 5 packages: `streamlit`, `openpyxl`, `pandas`, `pyinstaller`, and `pytest`). Meanwhile, empirical read-only inspection of the real operational `data/` corpus (`71` `IMP-*` folders + `2` root `.xlsm` = **`593` files, `518.50 MB`** / `543,690,245` bytes) proves that **`58.7%` (`348/593`)** of operational files are `.pdf`, `.msg`, `.xls`, `.eml`, `.jpeg`, `.pptx`, `.zip`, `.db`, or misnamed `.a` files that ReconcileAI either skips or crashes on today.

This proposal defines a modular, offline-capable **Track E Architecture** that extends M3's **8 shared application services (`src/services/`)** and M2's **SAP ECC 6.0 (`6.00.29`) Knowledge Base** without violating three non-negotiable engineering boundaries:
1. **Deterministic Math Sovereignty (R1 & R6):** All unit arithmetic (`int`), prorated unit costs and NCR totals (`Decimal` `ROUND_HALF_UP`), BOM curves, `Mov 101 - Mov 102` balances, Zero-Carton rules, and `.xlsm` patching remain exclusively inside `ReconciliationService`, `ValidationService`, `ExportService`, and `FormattingService`. Track E document extractors may only emit staged `CandidateExtractedDocument` proposals requiring mandatory human review; LLMs, VLMs, RAG, and MCP tools **never** compute or override authoritative figures.
2. **Offline Portability & Primary/Fallback UI Alignment:** The core Windows `--onedir` portable distribution (`dist/ReconcileAI_Portable.zip`, currently `134.2 MB`) remains lean, air-gapped (eliminating `app.py:313`'s external `icons8.com` fetch), and aligned with M3's **PySide6** primary desktop shell (`ui_desktop/`) and **Refactored Neutral-Gray Streamlit** fallback (`ui_web_fallback/`). Optional heavy AI runtimes (`[ocr]`, `[rag-vector]`, `[ai-local]`, `[vlm]`, `[mcp]`, `[automation]`) live strictly behind `pyproject.toml` optional extras—and multi-GB LLM weights or PyTorch are **never** bundled into the core portable ZIP.
3. **Operational Companion & SAP Read-Only Safety:** AI assistance integrates into M3's `Dock Panel (F1)` (`360px` right `QDockWidget`), unified CLI, and read-only MCP surface as a context-pinned, citation-backed analyst aid—never a generic chatbot, never hiding `needs_env_check`/`conflicting`/`unverified` caveats, and enforcing a strict three-layer prohibition against SAP write operations (`MIGO`, `MIRO`, `VL31N`, `MR11`, `SE16N &SAP_EDIT`, write RFCs/BAPIs).

## 3. Document Processing, Packing List Extraction, OCR & Vision Models (VLMs)

### 3.1 Essential (Priority #5 Core) vs. Optional Future Extensions

- **Essential (Priority #5 Core — Permissive, 100% Offline, CPU-Friendly):**
  1. **Magic-Byte Sniffing & Lock/Artifact Filtering (`DiscoveryService`):** Exclude `~$*` locks (`1` in `data/`), `Thumbs.db` (`4`), and output artifacts; inspect leading magic bytes (`%PDF-`, `D0 CF 11 E0`, `PK\x03\x04`, RFC-5322 MIME headers, JPEG SOI `FF D8 FF`) before dispatching to any `DocumentAdapter`. This automatically recovers misnamed files like `.a` $\rightarrow$ `%PDF-1.6` (`41050 IMPORTADORA ALMACEMA S.A`).
  2. **Deterministic Spreadsheets (`OpenXmlAdapter` / `LegacyBiffXlsAdapter` + Vendor `.xlsx` Normalizer):**
     - Add `python-calamine` (**MIT**, unified `.xls`/`.xlsx`/`.xlsm`) or `xlrd>=2.0.1` (**BSD-3-Clause**, pure Python `~200 KB`) behind the `[xls]` extra (covering **62/62** BIFF8 `.xls` files offline with zero Excel COM or LibreOffice dependency).
     - **Adapter-Level `PII_EXCLUSION_RULE`:** Both `OpenXmlAdapter` and `LegacyBiffXlsAdapter` enforce a strict domain sheet allowlist (`CONTROL DATA`, `BASE DE DATOS`, `CIERRE RECEP`, `DATOS GENERALES`, `Bultos`, `PARA N.C RECEP.`, `CIERRE DESP*`, `STOCK CONTROL DE INVENTARIO*`, `PED-45*`, `PORTADA`) and scan the first `35 × 15` cells of any non-allowlisted or `Hoja*` tab for `Autorización de Deducción`, `Departamento de Nómina`, `Número de identificación o cédula`, or `MV :` + `998`—aborting cell extraction immediately so `Hoja1`/`MV 998` payroll PII (present in `81/147` readable `data/` `.xlsm` and `31/45` `sandbox_benchmark/` `.xlsm` files) never enters `IngestionResult`, `CandidateExtractedDocument`, FTS5, `doc_nodes`, or MCP (`§7.6`).
     - Build a deterministic **Vendor Packing List / Invoice Table Detector** (distinct from retired `src/heuristic_parser.py` and strictly banning `"vkp2"` from any cost mapping): scans rows `1..50` to locate multi-row headers (`STYLE NO`, `CTN NO.`, `QTY/CTN`, `TOTAL QTY`, `UNIT PRICE`, `DOZEN`/`PCS`, `Referencia` in `Traducción`), normalizes merged cells forward/down, aggregates split carton runs for the same SKU (`11*72 + 1*62` in `INVOICE 10136-26-EK--A.XLSX`), proposes `DOZEN` $\rightarrow$ `PCS` (`* 12`) conversions with explicit `"PRICE_PER_DOZEN_CONVERTED"` flags, and preserves exact `Decimal` representations against IEEE-754 cell values (`1252.8000000000002`).
  3. **Page-Level PDF Routing & Word-BBox Clustering (`PdfTextOcrAdapter`, `[ocr]` extra):**
     - **Digital Pages:** Use `pypdf` (**BSD-3-Clause**) for metadata/page count/`/Rotate` inspection and `pdfplumber` (**MIT**) + `pdfminer.six` (**MIT**) for per-page character counts and word bounding boxes (`extract_words()`). Cluster words by vertical row bands (`top`/`bottom` tolerance) and header-anchored horizontal column intervals (`x0`/`x1`) so borderless invoices and DUAs extract cleanly without mid-token splitting (`['Ap', 'olo']`).
     - **Scanned Pages & Images (`pypdfium2` + `rapidocr>=3.10.0` + `onnxruntime`):** When a page has extractable chars `< 20` and embedded images `> 0` (covering the `21` all-scanned PDFs and the scanned pages inside the `10` partial-hybrid PDFs such as `DUA 014236.pdf` and `*_merged.pdf`), stream **one page at a time** via `pypdfium2` (**Apache-2.0 / BSD-3-Clause**, **`6.44 MB`** unpacked for `5.0.0`, no Poppler binary) at **250–300 DPI** with **`MAX_RENDER_LONG_EDGE_PX = 4096`** graceful scale clamping (preserving all `24` `14"×8.5"` `4200×2550` landscape pages in `data/` at `~292.6 DPI` while preventing C-heap OOM on crafted PDFs), enforce `MAX_PDF_BYTES = 50 MB`, `MAX_PDF_PAGES_PER_FILE = 100`, `MAX_OCR_PAGES_PER_CASE = 150`, wrap `PdfDocument`/`PdfPage`/`PdfBitmap` in `try/finally` `.close()` lifecycle cleanup, apply `/Rotate` (`90°`/`270°` across the `9` rotated pages), and execute **CPU OCR** via **`rapidocr>=3.10.0`** (`<4,>=3.8`, **Apache-2.0**, native `opencv-python-headless`) + explicit **`onnxruntime`** (**MIT**). (`rapidocr-onnxruntime 1.4.4` is **rejected** because `Requires-Python: <3.13` excludes `Python 3.13.5` and its hard `opencv-python` dependency risks Qt/HighGUI DLL collisions with `PySide6`.)
     - **Offline PyInstaller Model & Wheel Bundling:** `rapidocr 3.10.0` bundles **`30.28 MB`** of `PP-OCRv6` multilingual ONNX weights (`es`/`en`/`ch`, covering Spanish diacritics `ñ`, `á`, `é`, `í`, `ó`, `ú`) inside `rapidocr/models/` for 100% offline execution (`--collect-data rapidocr`), whereas non-default `PP-OCRv5` `latin`/`en` weights require explicit local `model_dir` / `sys._MEIPASS` paths so zero runtime `requests` downloads from `modelscope.cn` ever occur. PyInstaller specs must declare `excludes=["opencv-python", "sympy", "mpmath"]` (preventing `cv2/` namespace/Qt conflicts with `PySide6` and saving `70.23 MB` if `onnxruntime<1.25` is used on `Python 3.10`) + `--hidden-import=onnxruntime`.
  4. **Email & Attachment Extraction (`MsgEmlAdapter`, `[mail]`/`[ocr]` extra):**
     - Parse `.eml` via Python stdlib `email` (**PSF**) and `.msg` directly via **`olefile`** (**BSD-2-Clause**, `0.47`) + **`compressed-rtf`** (**MIT**, `1.0.7`; **`0.37 MB`** unpacked). **`msg-parser 1.2.0` (`BSD-2`) is explicitly rejected**: it has been unmaintained since 2019, ignores MAPI `001E`/`001F` type suffixes, hardcodes `decode("utf-8", "ignore")` without checking `0x3FDE`/`0x3FF3` codepages (causing silent `cp1252` Spanish mojibake), fails `openstream` on 3+-level nested `.msg` attachments, and retains Python 2 `data_models.py` bugs.

**Priority #5 `IDNLF -> MATNR` (`EINA`) Join & `ConfirmedExtractionBatch` Cross-Check Contract:**
Before any `CandidateExtractedDocument` (`PACKING_LIST` / `INVOICE`) becomes a `ConfirmedExtractionBatch` for `IngestionPipeline` $\rightarrow$ `ReconciliationService`:
1. **`vendor_style` (`IDNLF`) $\rightarrow$ `sap_material` (`MATNR`) Deterministic Join:** Normalize `vendor_style` (`clean_string`, uppercase) and `sap_material` (`clean_material_code`, preserving alphanumeric SKUs like `'1E2'` and SAP `CHAR(18)` padding rules). Resolve strictly in priority order: (a) exact `sap_material` match against `CIERRE RECEP` `PrepackItem.material_code` (`Col E`), else (b) exact `vendor_style` (`IDNLF`) match against `CIERRE RECEP` `PrepackItem.vendor_material` (`Col D`, `src/parsers.py:368–369`) and/or a read-only exported SAP `EINA` (`MATNR`, `IDNLF`, `LMEIN`, `LIFNR`) snapshot (`src/validator.py:67–74`; `KNOWLEDGE_EXPANSION_PLAN.md:140`). `1:N` `IDNLF -> MATNR` matches or multi-PO rows `(material_code, order_po_43, source_row)` emit `AMBIGUOUS_IDNLF_MATCH` / `MULTI_PO_SPLIT` requiring explicit analyst disambiguation; `0` matches emit `UNMAPPED_VENDOR_STYLE` and are excluded from auto-merge.
2. **`DOZEN -> UN` Conversion & Mandatory Flags:** Compare extracted `uom` (`DOZEN`/`DZ`/`DOC` vs `PCS`/`UN`/`PRK`) against `PrepackItem.um` (`Col BC` / `CONTROL DATA` `'um'`). When `uom == "DOZEN"`, convert deterministically in `Decimal`: `total_units = qty_dozens * Decimal("12")` and `unit_price_un = unit_price_dozen / Decimal("12")` (retaining full `Decimal` precision internally; `ROUND_HALF_UP` only at formatted/NCR output), attaching **`PRICE_PER_DOZEN_CONVERTED`** (and **`QTY_DOZEN_NON_INTEGER`** if `total_units != int(total_units)`).
3. **Arithmetic Cross-Check (`CTNS * QTY_PER_CTN == TOTAL_QTY`):** Aggregate split carton runs for the same `(vendor_style, sap_material)` (e.g., `11*72 + 1*62 = 854` in `INVOICE 10136-26-EK--A.XLSX`). Assert `sum(cartons * units_per_carton) == total_units` (emitting **`CTNS_X_QTY_PER_CTN_PASS`** or blocking **`CTNS_X_QTY_PER_CTN_MISMATCH`**) and `unit_price * total_units == extended_amount` within `Decimal("0.01")` tolerance.
4. **`ConfirmedExtractionBatch` $\rightarrow$ `CIERRE RECEP` Staging Merge Rules:** Only human-confirmed rows map into `PrepackItem` Packing List staging fields: `Col AW` (`bultos_packing_list` = confirmed `int` cartons), `Col AX` (`unidades_packing_list` = confirmed `int` units), and `Col AY` (`empaque_str` = canonical run string `"11*72 1*62"` or curve, obeying `ExportService.apply_zero_carton_rule`). Never overwrite SAP `ME80FN` fields (`Col G` `quantity_inv_41_units`, `Col AE`/`AF` `unit_cost`) or Excel formulas (`Col H`, `AU`, `AZ`); emit deterministic comparison alerts (`PL_VS_DOC41_QTY_DIFF`, `PL_VS_DOC41_COST_DIFF`) for analyst triage.

### 4.2 Essential Baseline (Priority #6 Core): SQLite WAL + FTS5 + Relational Lineage

Rather than requiring an external vector or graph server for the core desktop product, **Essential Phase 6 RAG** uses Python's built-in **`sqlite3` in WAL mode with FTS5 (`bm25()`)** alongside `SapKnowledgeService`:
- **Why Lexical + Metadata Retrieval First:** At Ekono's KB scale (tens to a few hundred atomic Markdown entries + `6.00.29` verified Help Portal pages + `71+` historical `IMP-*` manifests), queries are dominated by **exact SAP codes and symbolic identifiers** (`ME80FN`, `STPO`, `101` vs `102`, `641` vs `643`, `EINA` vs `EINE`, `41...` vs `43...`, `CURVA_DESCUADRADA`) where dense embeddings alone frequently confuse neighboring codes (`641` vs `643`). FTS5 BM25 + exact `entry_id`/`issue_type` metadata joins retrieve the exact record deterministically with **`0 MB`** added to `ReconcileAI_Portable.zip`.
- **SQLite Relational Case Memory & SAP Lineage Graph (`doc_nodes` / `doc_edges`, Zero Payroll PII):** Populated deterministically by `IngestionPipeline` and `AuditTrailService` from `run_manifests/` and verified case summaries, storing the 1–3 hop operational lineage graph:
  `Import PO 430000xxxx` (`EKKO`/`EKPO`) $\rightarrow$ `Nationalization 410000xxxx` (`ME80FN` / DUA) $\rightarrow$ `Material MATNR` (`18`-char padded, `MM60`/`MARA`) + `Vendor Style IDNLF` (`EINA`) $\rightarrow$ `BOM MAST/STPO` (`STLNR`, `MENGE`) $\rightarrow$ `QC CONTROL DATA` + `Mov 101/102/501` (`MKPF`/`MSEG`) $\rightarrow$ `Store STO 4500xxxxxx` (`C101+`, `Mov 641/642/643`, `MB52`/`MB5T`) $\rightarrow$ `NCR 400000xxxx` (`PARA N.C RECEP.`).
  Recursive SQLite `WITH RECURSIVE` CTEs answer cross-PO (`MATERIAL_EN_MULTIPLES_PO`), split-container (`Parte A/B/C`), and Phase 2 dispatch (`CIERRE DESP`) lineage queries in milliseconds without a separate graph database.
- **Explicit `PII_EXCLUSION_RULE` for Indexes & Lineage:** `IngestionPipeline`, `AuditTrailService` SQLite FTS5, `doc_nodes`/`doc_edges`, and optional `VectorStore` backends are **strictly forbidden** from parsing, storing, embedding, or indexing `Hoja1` (`MV 998` `'Autorización de Deducción'`) employee payroll PII (`81/147` `data/` `.xlsm`, `31/45` `sandbox_benchmark/` `.xlsm`). `CaseDiscoveryResult` / `run_manifests/` may record **at most** a boolean presence flag and static sheet citation (`has_payroll_deduction_sheet: bool`, `excluded_sheets: [{"sheet_name": "Hoja1", "reason": "PII_EXCLUSION_RULE_MV998"}]`); only static `sap.movement.998` KB rules (zero employee/case PII) may exist in `docs/sap-knowledge/`.
- **Mandatory SQLite WAL Storage Placement Rule (Windows NTFS Local-Only):** Because real operational imports historically resided on cloud-synced mounts (e.g., `tools/operational_stress_test.py:29` `IMP_DIR = Path(r"I:\My Drive\IMP")`), **all mutable SQLite WAL databases** (`kb_fts.db`, `lineage.db`, `audit_index.db`, `vectors.db` for `sqlite-vec`) **must reside strictly on local non-synced NTFS storage under `%LOCALAPPDATA%\ReconcileAI\`** (e.g., `%LOCALAPPDATA%\ReconcileAI\index\` and `%LOCALAPPDATA%\ReconcileAI\state\`; fallback `Path.home() / "AppData" / "Local" / "ReconcileAI"` if `LOCALAPPDATA` is unset)—**never** inside `data/`, `IMP_DIR`, Google Drive (`My Drive`), OneDrive, Dropbox/SharePoint synced trees, or SMB/UNC shares (`\\server\share`) where `-wal`/`-shm` `mmap` and byte-range locks corrupt. Before `sqlite3.connect(...)`, **`StoragePathPolicy`** validates the resolved DB path (rejecting UNC paths, `DRIVE_REMOTE` via `GetDriveTypeW`, cloud-sync root markers, and `DATA_DIR` paths without confirmed local NTFS `GetVolumeInformationW`), opens with `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL; PRAGMA busy_timeout=5000;` (or `file:...?immutable=1` for read-only `_internal/` snapshots), and runs `PRAGMA wal_checkpoint(TRUNCATE)` on clean shutdown.

### 4.3 Qdrant & Dedicated Graph DB Evaluation (Windows Multi-Process Hazard)

- **Critical Windows Multi-Process Finding for `qdrant-client`:** `qdrant-client` (Apache-2.0) in local embedded mode (`QdrantClient(path=...)`) acquires an **exclusive, non-blocking `.lock` file** on its storage directory. Conversely, local-NTFS SQLite WAL + FTS5 supports concurrent multi-process readers natively.
- **Optional Future Extensions (Behind `VectorStore` / `GraphStore` Protocols):**
  - *Tier 1 Local Dense Vector (`[rag-vector]`):* `fastembed` (**Apache-2.0**, `onnxruntime` CPU, pre-bundled quantized multilingual ES/EN ONNX model via `--add-data` + `HF_HUB_OFFLINE=1` to avoid `200 MB–1 GB+` PyTorch/`sentence-transformers` bloat) paired with `sqlite-vec` (**MIT/Apache-2.0**, multi-process SQLite extension under `%LOCALAPPDATA%\ReconcileAI\`) or single-process `QdrantClient(path=...)` strictly inside desktop-only mode to bridge Spanish/English warehouse slang (*"bultos pico"* $\leftrightarrow$ *"odd lot / complement carton"*).
  - *Tier 2 Multi-Client Qdrant Server (`[rag-qdrant]`):* Standalone `qdrant.exe` local sidecar or corporate Docker host (`QdrantClient(url="http://localhost:6333")`) carrying the 12 YAML fields as Qdrant payload filters if the corpus grows beyond ~50,000 PDF/email chunks across concurrent users.
  - *Tier 3 Dedicated Graph Store (`kuzu` / `networkx`):* Optional property-graph GraphRAG over multi-year `IMP-*` supplier/SKU discrepancy histories only if SQLite recursive CTEs hit expressive or latency limits.
- **Priority #6 `VectorStore` Deterministic Metadata Pre-Filter Contract Tests (`tests/contracts/test_vector_store_contract.py`):** Every `VectorStore` backend (`SqliteFts5Store`, `SqliteVecStore`, `QdrantVectorStore`) must pass an identical parametrized contract suite before backend swap or deployment:
  1. *Pre-Filter Before Top-`k` Cutoff:* Seed `k` high-similarity `sap_release="S4HANA"` / `verification_status="conflicting"` (`VL31N`/`RFUI`) chunks and `1` lower-similarity `sap_release="ECC_6.0"` / `verification_status="confirmed"` chunk; querying `top_k=1` with `{sap_release in {"ECC_6.0", "release_agnostic"}, verification_status == "confirmed"}` must return the `ECC_6.0` chunk (`len == 1`) and `0` `S4HANA`/`conflicting` chunks.

## 7. Mandatory Non-Negotiable Guardrails (R1 & R6) & M3 UI Integration

### 7.1 Deterministic Math Authority
`CandidateExtractedDocument` / `CandidateLineItem` DTOs (carrying `confidence`, `raw_text`, and `CellCoordinate`/`BoundingBox`) are strictly segregated at the type and service boundary from `PrepackItem`, `ChildSKU`, and `ReconciliationSummary`. `ReconciliationService`, `ValidationService`, `ExportService`, and `FormattingService` accept only human-confirmed `Decimal` (`ROUND_HALF_UP`) and validated `int` inputs. Any LLM/VLM/MCP response attempting to modify `received_real_units`, `ncr_amount`, `bultos`, `AS:AT`/`AW:AY` strips, or `Mov 101 - 102` balances is rejected and logged in `AuditTrailService`.

### 7.2 Evidence & Limitations Transparency + M3 `Dock Panel (F1)` Integration
Every Track E AI, RAG, CLI `--json`, and MCP response wraps its payload in a mandatory `GroundedResponseEnvelope`:
- `deterministic_facts`: Authoritative values computed by `src/services/` and formatted via `FormattingService`.
- `kb_citations[]`: `{entry_id, title, source_type, sap_release, sap_doc_version, verification_status, source_citation[], ai_usage_policy}`.
- `extraction_provenance[]`: `{source_path, container_chain, sheet_or_page, row_or_bbox, adapter_name, confidence}`.
- `limitations[]`: Mandatory explicit disclosures (e.g., `"Knowledge Index Not Built (Roadmap #4 Pending)"`, `needs_env_check`, `conflicting`, `unverified`, Blind Setup `PAUSA_SIN_CONTROL_CALIDAD`, OCR low-confidence `< 0.85`, `"Deterministic Mode (LLM Unavailable)"`, and `dlp_mode` disclosure such as `"DLP_REDACTED_MODE: vendor identities, costs ($), NCR totals, raw paths, and email/OCR text withheld"`).

In M3's **PySide6 Primary UI** (`REDESIGN_SPECIFICATION.md §4.3`), Track E renders strictly inside **`Dock Panel (F1)`** (`360px` right `QDockWidget`, neutral gray `#F3F4F6`/`#FFFFFF`, `1px` `#D1D5DB` borders, restrained slate-blue `#1D4ED8`, `16×16` monochrome SVGs, **zero emojis, zero gradients, zero dark neon surfaces, zero conversational chat bubbles**) and **View 1 Case Loader**'s `Non-Excel Corpus Summary` / candidate review staging drawer:

### 7.3 Operational Companion, Not Generic Chatbot
`Dock Panel (F1)` pins strictly to `(active_tab, material_code, order_po_43, source_row, active_issue_type)` and exposes only the 4 fixed operational cards (T-Code/Table Quick Reference, Movement Type & Stock Bucket Impact, Discrepancy Triage Checklist, Citations & Read-Only Boundary Footer) plus bounded parameterized actions (`Explain Active Issue`, `Inspect Lineage 43->41->45->40`, `Compare Similar Past IMP-* Cases`)—never an open-ended general-purpose chatbot.

### 7.4 Three-Layer SAP Write Prohibition
Consistent with **R1** (*"do not allow SAP write operations without explicit authorization and a separate safety design"*):
1. **Knowledge & Prompt Layer:** All KB entries carry `ai_usage_policy: read_only_guidance` (`ACTVT=03` display-only transactions; `SE16N &SAP_EDIT`, `MIGO`, `MIRO`, `VL31N`, `MR11` write steps prohibited).
2. **Adapter & MCP Layer:** `src/adapters/mcp_server.py` enforces a static read-only tool registry; `pyrfc` and SAP GUI scripting (`GuiSession` write) are omitted from all extras.
3. **CI / Pytest Boundary Guard:** Automated architectural tests verify zero prohibited SAP write libraries or transaction-execution wrappers exist in `src/`, and enforce the security/resource boundaries in `§7.6` (`Hoja1 MV 998` zero-PII indexing/leakage, MCP `--dlp-mode redacted` allowlist serialization, `IMPORT_ID_REGEX`/Zip Slip rejection, `StoragePathPolicy` local-NTFS enforcement, and `pypdfium2` `4096 px` clamp + `.close()` handle cleanup).

### 7.6 Security, DLP, PII Exclusion & Resource-Limit Boundaries

All Track E adapters, stores, LLM callers, CLI entry points, and MCP tools must satisfy these five normative security boundaries:
1. **`PII_EXCLUSION_RULE` (`Hoja1` / `MV 998` Payroll Deduction Protection):** `81/147` readable `data/` `.xlsm` workbooks (`31/45` in `sandbox_benchmark/`) contain populated `'Autorización de Deducción'` / `MV 998` payroll PII forms on `Hoja1` (`cédula`, salary consent, payroll fields), while `11` other `data/` `.xlsm` files carry unrelated `Hoja1` tabs. `OpenXmlAdapter` and `LegacyBiffXlsAdapter` enforce a domain sheet allowlist plus a hard content-signature block (`Autorización de Deducción`, `Departamento de Nómina`, `Número de identificación o cédula`, `MV :` + `998` across the first `35 × 15` cells). `IngestionPipeline`, SQLite FTS5, `doc_nodes`/`doc_edges`, optional `VectorStore`, `LlmProvider`, and `mcp_server.py` (both `redacted` and `local_trusted`) are **strictly forbidden** from storing, embedding, or returning `Hoja1`/`MV 998` PII; `run_manifests/` may record at most a boolean `has_payroll_deduction_sheet` flag and static exclusion reason.
2. **MCP `--dlp-mode` & `RedactedContextSerializer`:** `reconcileai mcp serve` defaults fail-closed to `--dlp-mode redacted`. `local_trusted` is permitted only with `--transport stdio` + explicit operator attestation (`--attest-local-host` or `mcp_local_trusted_attested = true`) + an `AuditTrailService` startup security log entry. Both `Mode 2 (cloud_redacted)` and MCP `redacted` share `RedactedContextSerializer`—a strict `pydantic` `ConfigDict(extra="forbid")` allowlist projection (`RedactedItemSummary`, `RedactedValidationIssue`, `RedactedKnowledgePayload`) using ephemeral per-session tokens (`VENDOR_A`, `CASE_001`, `MAT_001`, `STYLE_001`, `PO_43_A`, `DOC_41_A`) plus a secondary fail-closed check (`DlpBlockedError` on `@`, `$`/`USD`/`CRC`, unmasked `43`/`41`/`45`/`40`/`1100` IDs, or `Hoja1`/`998`), explicitly blocking raw `.msg`/`.eml` bodies, raw OCR/PDF text, `vendor_name`, `LIFNR`, `unit_cost`, `ncr_amount`, `description`/`observations`, `C101–C155`/`EC02`, `IM 01`/Ekono/Almacema, and host paths.
3. **Path-Traversal (`IMPORT_ID_REGEX`) & Archive/Email Resource Bounds:** CLI and MCP validate every `import_id` against `IMPORT_ID_REGEX = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._ \-()]{0,63}$")` (matching `71/71` `data/` and `15/15` `sandbox_benchmark/` folders), reject `..`, path separators, `:`, `\x00`, trailing `.`/spaces, and Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9`), and assert `(allowed_root / import_id).resolve(strict=True).is_relative_to(allowed_root)` (rejecting arbitrary MCP `root_dir` outside configured `allowed_roots`). `.zip` ingestion never calls `extractall()`, streaming via `zf.open()` with `is_relative_to(staging_root)` Zip Slip & symlink rejection, `0x800` / `cp437 -> utf-8 -> cp850 -> cp1252 -> cp437` decoding (`298.zip`, `Panamá.zip`), and container bounds shared with `.msg`/`.eml`: `MAX_CONTAINER_DEPTH = 2`, `MAX_ARCHIVE_ENTRIES = 250`, `MAX_SINGLE_MEMBER_BYTES = 50 MB`, `MAX_TOTAL_UNCOMPRESSED_BYTES = 200 MB`, `MAX_COMPRESSION_RATIO = 50.0` (measured on actual streamed bytes `> 1 MB`), and compact hashed staging filenames (`staging/<case_hash8>/<idx>_<sha256[:8]>_<safe_stem[:40]><ext>`) preventing Windows `MAX_PATH` failures.
4. **`pypdfium2` Rasterization Bounds & Native Lifecycle:** Enforce `MAX_PDF_BYTES = 50 MB`, `MAX_PDF_PAGES_PER_FILE = 100` (`data/` max is `44`), `MAX_OCR_PAGES_PER_CASE = 150`, and **graceful pixel downscaling** via `MAX_RENDER_LONG_EDGE_PX = 4096` / `MAX_RENDER_PIXELS = 4096 * 4096` (`effective_scale = min(target_dpi / 72.0, 4096 / max(w_pt, h_pt), sqrt(MAX_RENDER_PIXELS / (w_pt * h_pt)))`) so all `24` legitimate `14"×8.5"` (`4200×2550 px` at `300 DPI`) landscape pages in `data/` render cleanly at `~292.6 DPI` without C-heap OOM. Stream one page at a time with `try/finally` `bitmap.close()`, `page.close()`, and `doc.close()`.
5. **Prompt-Injection Isolation & Local-NTFS WAL Storage:** Keep system prompts static (zero raw vendor text); isolate untrusted email/PDF/`.xlsx` strings inside `<untrusted_document doc_id="..." role="..." trust="untrusted_data_only">` user blocks with closing-tag escaping, truncation caps, `pydantic` `extra="forbid"` output validation (`Mode 0` fallback), and MCP `untrusted_source_text` provenance wrapping under `local_trusted`.
